# Сценарий демонстрации

Документ нужен для записи минутного видео и живой защиты проекта.

## Цель демо

Показать законченный пользовательский сценарий:

```text
пользователь настраивает интересы
  -> сервис собирает новости
  -> AI анализирует новости
  -> пользователь получает персональную сводку
  -> пользователь запрашивает подробный AI-анализ
```

## Рекомендуемый режим для стабильной записи

Для первой записи использовать mock-режим:

```env
NEWS_FETCHING_PROVIDER=Mock
AI_PROVIDER=Mock
```

Для финальной защиты можно показать реальный режим:

```env
NEWS_FETCHING_PROVIDER=Rss
AI_PROVIDER=Yandex
```

Если внешние сервисы работают нестабильно, лучше записывать видео в mock-режиме, а на слайде отдельно показать, что Yandex AI подключается через конфигурацию.

## Подготовка перед записью

1. Запустить PostgreSQL:

```bash
docker compose up -d
```

2. Применить миграции:

```bash
dotnet ef database update \
  --project src/NewsSummarizer.Infrastructure \
  --startup-project src/NewsSummarizer.Api
```

3. Запустить API:

```bash
dotnet run --project src/NewsSummarizer.Api
```

4. Запустить Worker или выполнить debug pipeline вручную.

Ручной pipeline:

```bash
curl -X POST http://localhost:5000/debug/seed
curl -X POST http://localhost:5000/debug/fetch-news
curl -X POST "http://localhost:5000/debug/analyze-articles?limit=20"
curl -X POST http://localhost:5000/debug/build-daily-digests
curl -X POST http://localhost:5000/debug/build-opportunity-digests
curl -X POST http://localhost:5000/debug/send-urgent-notifications
curl -X POST "http://localhost:5000/debug/send-pending-notifications?limit=50"
```

## Минутный сценарий видео

### 0–10 секунд — проблема

Текст для озвучки:

> Каждый день появляется слишком много новостей. Пользователю сложно понять, что действительно важно, где повторы, а где есть полезная возможность.

Показать: Telegram-бот или слайд с названием проекта.

### 10–20 секунд — запуск бота

Действия:

```text
/start
/settings
```

Показать, что у пользователя есть настройки: категории, срочные темы, дайджесты.

Текст:

> Пользователь работает через Telegram-бота. Бот хранит профиль и настройки интересов.

### 20–35 секунд — AI pipeline

Показать терминал с выполнением debug endpoints или логи Worker.

Текст:

> Сервис собирает новости, удаляет дубликаты и отправляет материалы на анализ в AI. Модель возвращает структурированный результат: категорию, важность, срочность, summary и объяснение.

### 35–50 секунд — результат для пользователя

Действия в Telegram:

```text
/digest
/opportunities
```

Показать готовую сводку.

Текст:

> Пользователь получает не поток ссылок, а короткую персональную сводку: что произошло, почему важно и где читать источник.

### 50–60 секунд — подробный анализ

Действие:

```text
/analyze <articleId>
```

Текст:

> Если новость важна, пользователь может запросить подробный AI-анализ: последствия, риски и возможные гипотезы.

## Что обязательно проговорить на защите

- Проект решает задачу перегрузки новостями.
- AI встроен в pipeline принятия решений, а не используется как простой чат.
- Yandex AI Studio используется для структурированного анализа и генерации объяснений.
- Yandex Embeddings могут использоваться для семантической дедупликации.
- Telegram выбран как быстрый интерфейс для MVP.
- Worker делает сервис автоматическим, а не ручным набором запросов.

## Короткий pitch

> `news-summarizer` — это персональный AI-редактор новостей в Telegram. Сервис собирает новости из источников, убирает повторы, анализирует каждую новость через Yandex AI Studio и отправляет пользователю только важные материалы. AI оценивает категорию, срочность, полезность и объясняет, почему новость попала в сводку. Дополнительно embeddings помогают находить смысловые дубликаты, чтобы пользователь видел события, а не повторяющиеся статьи.
